# Withdrawing a claim for shared provenance discards one that was measured

**Measured 2026-08-16 on `5aae7a454..04af417d2`.**

A merge listed two properties as incidentally protecting a component. **I
refuted one and confirmed the other in the same message.** The reviewer then
withdrew **both**, on the grounds that the surviving one *"was made the same way
as the one you refuted"* — and the final increment re-listed it as **unmeasured**.

⇒ ***The correct response to "one of two claims from this source was wrong" is
to check the other, not to drop both.*** **Shared provenance is a reason to
verify, not a verdict** — and here the verification already existed in the
message that did the refuting.

⇒ **Say plainly that the withdrawal was right in METHOD and wrong in
CONCLUSION.** The instinct — distrust a source that produced one false claim —
is correct; **discarding a result that was independently measured is the
over-correction**, and it costs a re-measurement someone has already done.

**But do not call the axis safe either.** Re-running it showed the protection
now comes from **two pins built for different axes**. ⇒ ***Measured-true and
incidentally-protected are both true at once***, and reporting only the first
would leave the same fragility the node kept rediscovering. **Fifth instance on
one node of a property holding because of what the corpus happens to contain.**

## A REPORT THAT WRITES DOWN TWO OF THREE PARAMETERS DROPS THE ONE THAT MOVES MOST

The emitted report printed **fuel** and **stack** and omitted **build profile**,
which appeared only in the module doc. ⇒ **The same artifact demonstrates the
re-takeability discipline twice and omits it once.**

⇒ ***And it omitted the parameter matched to the headline's own units***: fuel
and stack move the number by a factor; debug-versus-release moves it by orders
of magnitude, **and the headline result was stated in orders of magnitude.**
**Check which parameter shares units with the claim** — that is the one whose
absence makes the claim unreproducible rather than merely imprecise.

## UPGRADE "VERIFIED BY READ" TO A STRUCTURAL ARGUMENT WHEN YOU CAN

A timing control was flagged as *"the Architect verified the mechanism, but that
is a read."* ⇒ **The forced side was not the load-bearing part.** The timed
interval includes parsing a source string that **grows with depth**, so the
forced measurement alone conflates the cost with input size — **what makes the
figure mean anything is that the baseline embeds the SAME source and the
reported quantity is the difference.**

⇒ ***Find the confound the control cancels, and the reading becomes an
argument.*** That is worth more than repeating the run, because it holds for
every future run rather than the one observed.
