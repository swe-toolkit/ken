## Objective

Derive, validate, and install ONE closed compile-time relation that gives the
governed descendant invocation the COMPLETE key it needs to call the EXISTING
`checked_ih_continuation_inheritance_for_invocation` at generated-function entry

## Named prior-art hazards the controls must answer (Research Q2)

1. **Under-keyed specialization caches return wrong code** (Lean
   `tests/elab/specialize_cache_miscompile.lean`; LCNF `Specialize.lean` caches a
   closed key before recursion). A and B must receive different keys even though
   body and final target agree, and interning ORDER must not change the
   association. Answered by AC-SPLIT-CROSS-PAIR and AC-SPLIT-PERMUTE.
2. **Pre-retarget reachability becomes false after retargeting** (LLVM PR
   #154668). Check bijection on the FINAL graph; each identity retargets exactly
   once and the old context retains no governed caller. Answered by
   AC-SPLIT-CLOSURE and AC-JOIN-TOTAL.
3. **Reused clone identity leaves stale auxiliary state** (LLVM #58759). Rebuild
   every context-indexed projection from the FINAL interner; never retain an old
   numeric id, `OwnedContext`, or declaration because a prefix agrees. Answered by
   AC-SPLIT-REBUILD and AC-BLAST-RADIUS.
4. **Bulk replacement violates target type/ABI** (LLVM #55000). Reconcile each
   retargeted caller with the FINAL context's parameter/capture runs and fail a
   wrong context/key BEFORE lowering. Answered by AC-SPLIT-DESCRIPTOR.
5. **Recursive specialization diverges when keys grow with traversal history**;
   over-merging risks wrong code. Answered by AC-SPLIT-CLOSURE's exact count
   clause: replacement-context count equals distinct incoming identities,
   non-collided contexts stay one, and rebuilding mints none.

## Acceptance criteria

- **AC-JOIN-ROW** (complete key, mints nothing) — each
  `CheckedIhGeneratedEntryAccess` row carries the exact `ContinuationContextId`,
  its context key `(enclosing specialization, worker body)`, the full existing
  `ContinuationCallIdentity`, and the final descendant coordinate `(binding,
  invocation, call, callee)`. A control that strips any one of those four groups
  REDDENS. The row copies or remints NO `K`, locator, transport, or fresh-result
  destination — a control asserting each of those four is obtained only through
  the existing accessor REDDENS if the row carries its own copy.
- **AC-JOIN-TOTAL** (totality and exact bijection, on the FINAL graph) — the
  planner validator re-derives the relation from the same planner graph and
  requires totality and exact bijection over EVERY governed final arrival hosted
  by an emitted generated context: no absent row, duplicate row, wrong context,
  wrong source-call identity, wrong destination owner/body, or wrong final
  invocation/callee/binding. Measured on the FINAL post-retarget graph, not the
  pre-retarget one (hazard 2). This is the node's own totality obligation; the
  Research census decided the branch and does NOT discharge it.
- **AC-JOIN-RESOLVES** (through the existing accessor, view unchanged) — every
  validated row resolves through the EXISTING
  `checked_ih_continuation_inheritance_for_invocation` to the exact existing
  inheritance view, and that view's capability locator and fresh-result
  destination are then checked UNCHANGED. No descendant-only accessor and no
  second search route exists anywhere in the diff.
- **AC-SPLIT-POSITIVE** (the REAL collision is the mandatory positive) — the
  governed write witness's actual A/B collision at `ContinuationContextId(0)` /
  key `(3, 1238)` / final coordinate (invocation 741, call 740, callee 739,
  `CheckedIhBinding { frame_origin: 737, recursive_position: 1 }`) is split into
  two distinct generated contexts, one per incoming identity, with identity A
  (source target 0, result origin 1227, construct origin 1107) and identity B
  (source target 1, result origin 1228, construct origin 1043) each retargeted to
  its own. **A generic context-sharing mutation is NOT a substitute**: it tests
  rejection of synthetic input and cannot discharge the actual governed
  population. The generic mutation is still required as AC-SPLIT-MUTATION below,
  in ADDITION to this one.
- **AC-SPLIT-CROSS-PAIR** (the new key member is what does the work) — installing
  A's row on B's split context, and B's row on A's, each INDEPENDENTLY REJECTS.
  Destination context, body, and final occurrence all still agree in both
  directions; ONLY the opaque source-call identity differs. This is the control
  that proves the new key member is load-bearing rather than decorative, and it
  answers hazard 1.
- **AC-SPLIT-CLOSURE** (SET equality, not counts) — the governed incoming
  source-call identities for the collided old key, the source-identity components
  of the replacement context keys, the installed rows, and the retargeted callers
  are equal AS SETS. Counts alone permit an A/A substitution for A/B and must not
  be accepted. Additionally, and as exact counts: the replacement-context count
  equals the number of distinct incoming identities; each identity retargets
  exactly ONCE; the old context retains NO governed caller; a non-collided context
  stays exactly one; and rebuilding mints no context that no identity requires
  (hazards 2 and 5). The read compilation, which has no collision, must show an
  unchanged context count.
- **AC-SPLIT-PERMUTE** (numbering is not identity) — permuting the context
  interning order may change the dense `ContinuationContextId` numbers, but the
  key/source-identity/row/caller ASSOCIATION must not change. A control that
  permutes the order and asserts association stability passes; one that asserts a
  fixed numeric id is not accepted as evidence (hazard 1).
- **AC-SPLIT-REBUILD** (no stale auxiliary state) — every context-indexed
  projection is rebuilt from the FINAL interner. No old numeric id, `OwnedContext`,
  declaration, or derived table survives because a key prefix agrees. A control
  that retains one stale projection entry REDDENS (hazard 3).
- **AC-SPLIT-DESCRIPTOR** (reconcile before lowering) — each retargeted caller is
  reconciled with the FINAL context's parameter/capture runs, and a wrong
  context/key FAILS BEFORE lowering rather than at or after it. A no-old-context
  residual check accompanies it: after retargeting, no governed reference to a
  replaced context remains anywhere (hazard 4).
- **AC-SPLIT-ROOTS** (both roots, each with its own row) — BOTH split function
  roots are exercised, and each retains its OWN compile-time row across generated
  re-entry while `SourceControl` remains identity-free. A one-root control is NOT
  accepted: it passes with both callers routed to A, which is exactly the defect.
- **AC-SPLIT-MUTATION** (synthetic non-functional join) — a context-sharing
  mutation that makes the join non-functional must either produce the ruled
  context split or REJECT. It must never silently select one row.
- **AC-ENTRY-COMPLETE** (consumer-adjacent, per-identity, not aggregate) — an
  instrument immediately at the REAL D3A call seat inside the generated-context
  lowering path observes, on the unchanged read program and the independently
  derived write program, ONE arrival for identity A and ONE for identity B,
  **each separately** resolving through the existing full accessor to its OWN
  view, its OWN typed locator, its OWN in-range current environment binding
  `Value(Carried(_))`, and its OWN fresh-result destination. **Aggregate "two
  arrivals were observed" evidence is NOT accepted.** The instrument does NOT
  apply `K` and does NOT bind `R2`. This AC is what discharges "no further
  retrieval or entry-boundary component is left undiscovered" and it is the gate
  the three narrow predecessors each lacked.
- **AC-KEY-NEGATIVES** (wrong facts reject) — INDEPENDENTLY: a wrong context id;
  a wrong context key; a wrong opaque call identity carrying the SAME apparent
  target; a wrong final invocation, callee, or binding; and a wrong locator domain
  or index each REJECT.
- **AC-MUTATIONS** (removal + duplication, PER SPLIT PAIR, byte-clean restore) —
  INDEPENDENTLY and per split pair: removing A's row fails A while B remains
  observable; duplicating A's row REJECTS rather than being hidden by B's
  presence. Read and write are derived independently from their own planner facts
  and never cross-used; every mutation restores BYTE-IDENTICALLY.
- **AC-BLAST-RADIUS** (name the outward surface, gate on it) — the refined

- **AC-INERT** (behaviorally inert at the product) — D3A is still ABSENT on

- **AC-NO-RUNTIME-CARRIER** (the carrier is compile-time, structurally) — the
