# Backend split census: type ownership

Measurement SHA: `4de48651434dd6340f81ec9b1b7a5ac2ec8c0199`

This inventory is the type-ownership part of `RT-BACKEND-SPLIT-CENSUS`.
It records every non-private type declaration in the measured backend scope,
then groups declarations that have identical visibility, mint-shape, and
consumer sets. The declaring file is the owning module.

## Boundary and selector

The declaration domain is every Rust file below
`crates/ken-runtime/src/cranelift_backend/` plus
`crates/ken-runtime/src/boundary_value_clif.rs`. The exact selector is:

```text
^\s*(pub(?:\([^)]*\))?)\s+(struct|enum|type)\s+([A-Za-z_][A-Za-z0-9_]*)
```

It selects 278 non-private type declarations: `pub` 24, `pub(crate)` 8,
`pub(in crate::cranelift_backend)` 199, `pub(super)` 47. It cannot see private
types, macro-generated declarations, declarations
whose visibility and type keyword are split across lines, traits, constants,
functions, or fields. `pub(in crate::cranelift_backend)` alone accounts for
199 declarations;
the broader inventory retains the other visibility classes because they are
also cross-module move constraints.

Consumer search covers every `*.rs` file under `crates/ken-runtime/src/` and
uses an identifier-boundary match. A consumer set therefore records lexical
reference files, not dynamically executed consumers. A mint-shape file is a
consumer containing `Type {`, `Type(`, or `Type::`; this catches struct/tuple
construction and enum variants, but it can overcount associated-item reads
and cannot see construction hidden by aliases or macros. `none` means no hit
under that selector, not that no semantic consumer exists.
